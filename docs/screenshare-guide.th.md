# คู่มือตรวจเครื่องระหว่างแชร์หน้าจอ

สำหรับแอดมินเซิร์ฟเวอร์ที่ตรวจเครื่องผู้เล่นผ่านการแชร์หน้าจอ และสำหรับผู้เล่นที่ถูกตรวจ ใช้กับ aeterna-rongroi
**0.3.0** · Read in English: [screenshare-guide.md](screenshare-guide.md)

> ⚠️ **ยังเป็นรุ่นทดลอง (pre-alpha)** รุ่น 0.3.0 มี rule 21 ตัว และ 20 ตัวยังเป็น `experimental` อย่าแบนใครเพราะสิ่งที่
> โปรแกรมนี้แสดง และอย่าใช้มันยืนยันว่าใครไม่ผิด

## 1. แสดงอะไรได้ และแสดงอะไรไม่ได้

| แสดงได้ | แสดงไม่ได้ |
|---|---|
| การตั้งค่าเครื่องที่ทำให้โปรระดับ kernel โหลดได้ง่ายขึ้น ได้แก่ Secure Boot, test signing, memory integrity (HVCI), TPM และยังดูได้ว่าเฟิร์มแวร์กับ Windows รายงาน Secure Boot ตรงกันไหม และมีนโยบายระดับเครื่องหรือระดับผู้ใช้ปิดการบันทึก script block ของ Windows PowerShell หรือ PowerShell 7 หรือไม่ | โปรที่รันบน **เครื่องที่สอง** (DMA) ซึ่งไม่ทิ้งอะไรไว้บนเครื่องที่ถูกตรวจ |
| ว่า Security log หรือ event log ไฟล์หนึ่งมีบันทึกว่าตัวเองถูกล้าง | overlay ที่ซ่อนตัวจากการจับภาพหน้าจอ |
| ว่าการตรวจแต่ละข้อได้คำตอบไหม ถ้าไม่ได้ ติดอะไร | อะไรเลย ถ้า Windows บนเครื่องนั้นถูกแก้ให้หลอกโปรแกรมที่รันอยู่บนมัน |
| | ว่าเครื่องสะอาด **ไม่มีผลลัพธ์ข้อไหนแปลว่าอย่างนั้น** |

ทุกแถวเป็นหนึ่งในสามสถานะ **เจอ** แสดงหลักฐาน **ไม่เจอ** บอกว่าแหล่งนั้นย้อนดูได้ไกลแค่ไหน **ยังไม่ได้วัด** บอกเหตุผล
คนเป็นผู้ตัดสินว่าแต่ละแถวหมายถึงอะไร โปรแกรมไม่ตัดสินเอง

## 2. โหลดไฟล์ตัวจริง

1. ให้ผู้เล่นโหลดเองจากหน้า **Releases** ของโปรเจกต์บน GitHub ส่งลิงก์หน้านั้นให้ผู้เล่น อย่าส่งไฟล์ให้เอง
   - `aeterna-rongroi-cli-0.3.0-windows-x64.exe` คือรุ่นบรรทัดคำสั่ง ไม่ใช้ WebView2
   - `aeterna-rongroi-0.3.0-windows-x64.exe` คือรุ่นที่มีหน้าต่าง
2. อย่าเปิดไฟล์จากเบราว์เซอร์ Windows SmartScreen จะขึ้นเตือน เพราะ release ยังไม่ได้เซ็นโค้ด และต้องเช็ค hash ก่อน
3. ก่อนเปิดโปรแกรม ให้ผู้เล่นเปิด PowerShell ในโฟลเดอร์ที่โหลดไฟล์มา แล้วรัน:

   ```powershell
   Get-FileHash .\aeterna-rongroi-*-windows-x64.exe
   ```

   เทียบ hash กับบรรทัดของไฟล์ชื่อเดียวกันใน `SHA256SUMS` บนหน้า release ตัวพิมพ์เล็กหรือใหญ่ไม่มีผล
4. เมื่อ hash ตรงแล้วเท่านั้น: `Unblock-File .\<ชื่อไฟล์>` จะเอาเครื่องหมาย "โหลดมาจากอินเทอร์เน็ต" ออกจากไฟล์นั้นไฟล์เดียว
   ถ้า SmartScreen ยังขึ้น **Windows protected your PC** ให้กด **More info** ดูชื่อแอป แล้วกด **Run anyway**
   ช่อง publisher จะขึ้นว่าไม่รู้จักจนกว่า release จะเซ็นโค้ด อย่าปิด SmartScreen ทั้งเครื่อง
5. ตอนรัน ส่วนหัวต้องขึ้นว่า **build ทางการ** ถ้าขึ้น **UNOFFICIAL BUILD** หรือ hash ไม่ตรง **ให้หยุด** ผลตรวจใช้ไม่ได้

ส่วนหัวของรายงานรุ่น CLI พิมพ์ `exe sha256` ของตัวโปรแกรมเองด้วย ในรุ่นที่มีหน้าต่าง ค่านี้ไม่อยู่ในส่วนหัวของรายงาน
ให้เปิด **เกี่ยวกับ & ดูโค้ด** ซึ่งแสดงค่านี้เป็น **SHA-256** ค่านี้ควรตรงกับ `SHA256SUMS` ถ้าตรง แปลว่าไฟล์ที่รันอยู่
สอดคล้องกับ release แต่พิสูจน์ไม่ได้ เพราะโปรแกรมที่ถูกแก้จะพิมพ์ค่าอะไรออกมาก็ได้

## 3. สิทธิ์ผู้ดูแลระบบ

การตรวจบางข้อต้องใช้สิทธิ์ผู้ดูแลระบบ รายงานจะบอกจำนวนไว้บรรทัดเดียวเหนือหลักฐาน:

> ขอบเขตการตรวจ: มี N รายการที่ตอบไม่ได้เพราะการสแกนครั้งนี้ไม่มีสิทธิ์ผู้ดูแลระบบ
> เปิดใหม่ด้วยสิทธิ์ผู้ดูแลระบบแล้วจะตอบได้

บรรทัดนี้ไม่ใช่สิ่งที่ตรวจเจอ มันบอกว่าการสแกนรอบนี้ตอบรายการเหล่านั้นไม่ได้ ผลที่วัดบนเครื่อง Windows 11
หนึ่งเครื่องตอนไม่มีสิทธิ์ผู้ดูแลระบบ: Prefetch กับ BAM แทบไม่ได้อะไร rule ล้าง log ทั้งสองตัวออกมาเป็น *ยังไม่ได้วัด*
ส่วน rule posture สี่ตัวที่มีในรุ่น 0.2.0 กับ PCA ทำงานปกติ
rule ใหม่ในรุ่น 0.3.0 อีกสี่ตัวก็ออกมาเป็น *ยังไม่ได้วัด* ตอนรันแบบไม่มีสิทธิ์ผู้ดูแลระบบ และนับรวมอยู่ในบรรทัดนั้น
คือ rule ที่อ่านสถานะ Secure Boot จากเฟิร์มแวร์เอง rule สองตัวเรื่องไฟล์ Prefetch หรือไฟล์ event log ถูกตั้งเป็นอ่านอย่างเดียว
และ rule เรื่องไฟล์ event log ที่ไม่ใช่ไฟล์ที่ Windows เขียน channel ของมันลงไป
([ADR 0037](adr/0037-prefetch-configuration-and-the-read-only-attribute.md),
[ADR 0038](adr/0038-firmware-secure-boot-and-script-block-logging-policy.md),
[ADR 0042](adr/0042-what-the-event-log-service-says-a-channel-writes.md))

- **รุ่นที่มีหน้าต่าง:** ที่หน้าแรก กด **ตรวจด้วยสิทธิ์ผู้ดูแลระบบ** แล้วกดยอมรับในหน้าต่างที่ Windows ถาม โปรแกรมจะปิด
  แล้วเปิดใหม่ด้วยสิทธิ์นั้น และเริ่มสแกนใหม่ทั้งหมด ปุ่มนี้ขึ้นเฉพาะตอนที่การสแกนรอบนั้นไม่มีสิทธิ์ผู้ดูแลระบบ
- **CLI:** เปิด **PowerShell แบบ Run as administrator** แล้วสแกนในหน้าต่างนั้น (ข้อ 4)
  `--elevate` จะสแกนใน **หน้าต่าง console ใหม่** แทน รุ่น 0.3.0 เปิดหน้าต่างนั้นค้างไว้จนกว่าจะกด Enter
  ([ADR 0012](adr/0012-elevation-relaunch.md)) แต่รายงานจาก `--elevate` จะอยู่ในหน้าต่างนั้น และไม่เข้าไฟล์ที่ redirect ด้วย `>`
  ถ้าใช้รุ่น 0.2.0 อย่าใช้ `--elevate` เพราะ Windows ปิดหน้าต่างนั้นทันทีที่สแกนเสร็จ รายงานหายไปพร้อมหน้าต่าง
  (วัดบนเครื่อง Windows 11 จริง)

ผู้เล่นปฏิเสธสิทธิ์ผู้ดูแลระบบได้ การสแกนยังรันได้ แค่มีรายการในบรรทัดขอบเขตมากขึ้น

## 4. สแกนแบบโหมด SS

โหมด SS คือมุมมองสำหรับแชร์หน้าจอ ขอความยินยอมจากผู้เล่นก่อน แสดงสิ่งที่ตรง rule กับ timeline ของเวลาที่หน้ายินยอมระบุไว้
และเปลี่ยนโฟลเดอร์ผู้ใช้ใน path เป็น `%USERPROFILE%`

**รุ่นที่มีหน้าต่าง:** **ตรวจระหว่างแชร์หน้าจอ (โหมด SS)** → อ่านหน้ายินยอม → **ยินยอม — แสดงผลโหมด SS**
รุ่นนี้สแกนตอนเปิดโปรแกรม **ก่อน** หน้าต่างจะขึ้น หน้าต่างจึงเปลี่ยนผลไม่ได้ หน้ายินยอมมีผลแค่ว่าจะแสดงอะไร

**CLI:**

```powershell
.\aeterna-rongroi-cli-0.3.0-windows-x64.exe scan --mode ss --lang th
```

โปรแกรมจะถาม `ดำเนินการต่อ? [y/N]` และ **ผู้เล่น** เป็นคนตอบ

- **อย่าใช้ `--yes` ข้ามคำถามที่ผู้เล่นยังไม่ได้ตอบ** flag นี้มีไว้สำหรับผู้เล่นที่ยินยอมไปแล้ว
- ถ้าผู้เล่นปฏิเสธ โปรแกรมจะพิมพ์ `ยกเลิกการสแกนแล้ว ไม่ได้อ่านอะไรเลย` และไม่อ่านอะไร ส่วนเซิร์ฟเวอร์จะทำอะไร
  หลังผู้เล่นปฏิเสธ เป็นกติกาของเซิร์ฟเวอร์ ไม่ใช่สิ่งที่โปรแกรมนี้วัด

## 5. อ่านรายงาน

### ส่วนหัว

```
aeterna-rongroi 0.3.0
build ทางการ
mode: ss · windows <build> · สิทธิ์ผู้ดูแลระบบ · rules: <n> (<bundle hash>)
exe sha256: <hash>
Windows เริ่มทำงาน: <เวลา> (<วัน ชั่วโมง นาที> ก่อนการสแกนนี้) การกด "Shut down" ขณะเปิด Fast Startup (ค่าเริ่มต้นของ Windows) การ sleep และการ hibernate ไม่ทำให้ค่านี้เริ่มใหม่ การ restart ทำให้เริ่มใหม่
```

ดูสี่อย่าง: `build ทางการ`, `mode: ss`, ขึ้นว่า `สิทธิ์ผู้ดูแลระบบ` หรือ `ผู้ใช้ทั่วไป`, และจำนวน rule

**`Windows เริ่มทำงาน`** เป็นข้อมูลประกอบสำหรับอ่านเวลาในแต่ละแถว ไม่ใช่สิ่งที่ตรวจเจอ เวลาในรายงานเป็น UTC
แถวที่บอกว่า record เก่าสุดของ log หรือการล้าง log เกิดก่อนเวลานี้ แปลว่าเกิดก่อน Windows เริ่มทำงานครั้งล่าสุด
ถ้าเกิดหลังเวลานี้ แปลว่าเกิดหลังจากนั้น มีสี่เรื่องที่ต้องรู้:

- **ผ่านมาหลายวันเป็นเรื่องปกติ** ตามค่าเริ่มต้นของ Windows การกด **Shut down** ไม่ได้ปิด Windows จริง
  Fast Startup จะบันทึก Windows ลงดิสก์ แล้วเปิดเครื่องครั้งถัดไปก็ทำงานต่อจากเดิม Microsoft เขียนไว้ว่า fast startup
  คือสิ่งที่เกิดขึ้นตามค่าเริ่มต้นเมื่อสั่งปิดเครื่อง มีแค่ **Restart** หรือการปิดเครื่องตอนที่ปิด Fast Startup ไว้
  ที่ทำให้เริ่มนับใหม่ ผู้เล่นที่ปิดเครื่องทุกคืนอาจเห็น "3 วัน" ตรงนี้ได้ บนเครื่อง Windows 11 เครื่องหนึ่งที่โปรเจกต์นี้ตรวจ
  การเริ่มทำงาน 27 ครั้งจาก 48 ครั้งที่ System log บันทึกไว้เป็นการทำงานต่อจาก Fast Startup
  ([ADR 0039](adr/0039-a-time-anchor-for-the-report.md))
- **sleep และ hibernate ก็ไม่ทำให้เริ่มนับใหม่** และเวลาที่เครื่อง sleep อยู่ก็ถูกนับด้วย
- **ถ้านาฬิกาถูกเปลี่ยน ค่านี้จะเลื่อน** ค่านี้คำนวณจากนาฬิกาของเครื่องตอนสแกน ถ้านาฬิกาถูกเปลี่ยนหรือถูกแก้หลังจากนั้น
  record ที่เขียนก่อนการเปลี่ยนจะใช้เวลาตามนาฬิกาเดิม บนเครื่องที่กล่าวถึงข้างบน record การเริ่มทำงานใน System log
  ห่างจากเวลานี้ 7 ชั่วโมงด้วยเหตุผลนี้
- **Windows ที่ถูกดัดแปลงรายงานเวลาอะไรก็ได้** เหมือนทุกอย่างในรายงาน ค่านี้คือสิ่งที่ Windows บอกโปรแกรม

### แต่ละแถว

```
[เจอ] ตรวจ: <ชื่อ rule>  (<strength>, <collector>)
    <หลักฐาน>
    เกี่ยวกับการตรวจนี้: <การตรวจนี้หมายถึงอะไร และพิสูจน์อะไรไม่ได้>
    เรื่องปกติที่ทำให้เกิดผลแบบนี้ได้เหมือนกัน:
      - …
```

- **`ตรวจ:`** อยู่หน้าชื่อ เพราะชื่อ rule บอกว่า rule มองหาอะไร ไม่ได้บอกว่าเห็นอะไร
- **strength** บอกว่า rule ให้หลักฐานแบบไหน `tamper`: ร่องรอยถูกลบหรือถูกแก้ `posture`: การตั้งค่าเครื่องที่ทำให้โกงง่ายขึ้น
  `presence`: มีไฟล์อยู่ แต่ไม่ได้บอกว่าเคยรัน `context`: ข้อมูลพื้นหลังให้คนตรวจ (มี `execution` ด้วย แต่ยังไม่มี rule ไหนใช้)
- **เรื่องปกติที่ทำให้เกิดผลแบบนี้ได้เหมือนกัน** ขึ้นข้างทุกแถวที่ `เจอ` **ให้อ่านออกเสียง** ทุก rule ต้องมีส่วนนี้
  และเป็นส่วนที่คนมักข้ามมากที่สุด
- **`ยังไม่ได้วัด (เป็นเรื่องปกติของเครื่องนี้)`** แปลว่าคนเขียน rule ระบุไว้ว่าสภาพเครื่องแบบนี้เป็นเรื่องปกติ
  **`ยังไม่ได้วัด (ไม่ได้คาดไว้)`** แปลว่าไม่ได้คาดไว้ ทั้งสองแบบไม่ใช่สิ่งที่ตรวจเจอ

### บรรทัดท้าย

```
ซ่อนในโหมด SS: ไม่เจอ <n> · ยังไม่ได้วัด (เป็นเรื่องปกติของเครื่องนี้) <n> · ยังไม่ได้วัด (ไม่ได้คาดไว้) <n> · สิ่งที่เห็นแต่ไม่ตรง rule ใดเลย <n>
```

เป็นจำนวนของสิ่งที่โหมด SS ไม่ได้แสดงเป็นรายการ เหตุผลอยู่ในข้อ 7

## 6. rule ทั้งหมด และเรื่องปกติที่ทำให้เกิดผลแบบเดียวกัน

| rule | strength | status | เรื่องปกติที่ทำให้เกิด (สรุปจากตัว rule เอง) |
|---|---|---|---|
| Secure Boot ถูกปิดอยู่ | posture | `test` | บูตแบบ legacy BIOS/CSM, ลงสองระบบ, ปิดเพื่อใช้เครื่องมือฮาร์ดแวร์หรือโอเวอร์คล็อก |
| เปิดโหมด test signing ของ Windows อยู่ | posture | `experimental` | คนเขียนหรือทดสอบ driver, วิศวกรฮาร์ดแวร์, ซอฟต์แวร์ที่คู่มือติดตั้งสั่งให้เปิด |
| ตั้งค่า Memory integrity (HVCI) ไว้เป็นปิด | posture | `experimental` | ฮาร์ดแวร์ไม่รองรับ, ปิดเพื่อแก้ driver ชนกัน, เครื่องจำนวนมากปิดมาตั้งแต่แรก |

  เมื่อ 2026-09-13 ซึ่งหมดอายุ 2027-09-05 ถ้าเห็นแถวนี้ในรายงานของผู้เล่นหลายคนโดยชื่อผู้เซ็นเหมือนกัน น่าจะเป็น
  ใบรับรองที่ต่ออายุแล้ว ให้ถือว่าแถวนี้ไม่ได้บอกอะไร ตรวจใบรับรองของ FiveM.exe ที่ติดตั้งใหม่จาก Cfx.re บนเครื่องตัวเอง
  แล้วแจ้งโปรเจกต์นี้

รายงานของรุ่น 0.2.0 มีแค่ rule หกตัวแรกในตารางนี้ สิบห้าตัวถัดมาเป็นของใหม่ในรุ่น 0.3.0 และสิบหกตัวสุดท้าย — ไดรเวอร์มีช่องโหว่ โฟลเดอร์ cache ของเซิร์ฟเวอร์ ไฟล์ hosts และอีกสิบสามตัวเรื่องเครื่องนี้ใช้ Windows แบบไหน — เพิ่มหลัง 0.3.0 ยังไม่อยู่ในรุ่นที่ออกแล้ว แถว posture ของเฟิร์มแวร์และของ PowerShell
ลำพังตัวมันไม่ได้แปลว่า "ไม่มีใครตั้งนโยบาย" หรือ "Secure Boot ปิด" แถวเฟิร์มแวร์ต้องมีสองค่าที่ไม่ตรงกัน แถว PowerShell แต่ละแถว
ต้องมีนโยบายที่ตั้งเป็นปิดจริง แถวระดับผู้ใช้สองแถวอ่านบัญชี Windows ที่ใช้รันการสแกน
ซึ่งเป็นของผู้เล่นก็ต่อเมื่อไม่ได้เริ่มการสแกนใหม่ด้วยรหัสผ่านผู้ดูแลระบบของคนอื่น rule เฟิร์มแวร์ไม่ได้ตรวจหาฮาร์ดแวร์ DMA (ข้อ 1)
และไม่ได้บอกอะไรเกี่ยวกับเครื่องที่สอง

rule สามตัวที่ว่าด้วยไฟล์ (ADR 0037, ADR 0042) บอกว่า **ไฟล์** Prefetch หรือไฟล์ log อยู่ในสภาพไหน ไม่ได้บอกว่าบันทึก
ในไฟล์เขียนว่าอะไร ไม่มีตัวไหนบอกว่าใครเปลี่ยนหรือเปลี่ยนเมื่อไร และบนเครื่อง Windows 11 เครื่องเดียวที่โครงการนี้วัดมา
ทั้งสามตัวออกมาเป็น "ไม่เจอ"

สามเรื่องที่ต้องรู้เกี่ยวกับ rule ไดรเวอร์มีช่องโหว่:

- **แค่มีโปรแกรมฮาร์ดแวร์ก็ขึ้นได้แล้ว** บน PC Windows 11 เครื่องเดียวที่โปรเจกต์นี้สแกน rule นี้ขึ้น
  "เจอ" สองแถว ทั้งสองเป็นไดรเวอร์ที่ ASUS เซ็น บนเครื่องที่ลงโปรแกรมการ์ดจอของ ASUS ไว้
  ([ADR 0048](adr/0048-the-driver-service-collector.md)) ไดรเวอร์ในรายชื่อของ LOLDrivers เป็นไดรเวอร์ของจริงที่มีลายเซ็น
  แต่มีจุดอ่อนที่รู้กันอยู่
- **ลงทะเบียนไว้ ไม่ได้แปลว่าโหลดอยู่หรือถูกใช้** แถวนี้บอกว่ามี driver service ชี้ไปที่ไฟล์นั้น ไม่ได้บอกว่าไดรเวอร์กำลังรัน
  ไม่ได้บอกว่ามีอะไรใช้จุดอ่อนของมัน และไม่ได้บอกว่าใครติดตั้ง แถวนี้แสดงชื่อ service, path ของไฟล์ และ SHA-256
  ให้เอา hash ไปค้นในรายการของ rule ([คู่มือ rule](rules-reference.th.md) บอกชื่อไฟล์) เพื่อดูว่าเป็นรายการไหนใน
  LOLDrivers แล้วถามผู้เล่นว่า service นี้เป็นของโปรแกรมอะไร
- **Windows อาจยังบล็อกไว้** Microsoft มีรายการไดรเวอร์มีช่องโหว่ของตัวเองที่ Windows ไม่ยอมโหลด โปรแกรมนี้ไม่ได้อ่านว่า
  รายการนั้นเปิดอยู่หรือไม่ และไดรเวอร์ที่อยู่ในรายชื่อของ LOLDrivers ไม่จำเป็นต้องอยู่ในรายการของ Microsoft

สามเรื่องที่ต้องรู้เกี่ยวกับการสแกนแบบ Full (ADR 0052, ADR 0055):

- **ผู้เล่นเป็นคนเลือกก่อนเริ่มสแกน** ในโปรแกรมที่เป็นคนอ่าน `scan --full` จะถาม และเริ่มเฉพาะเมื่อตอบ `yes` ใน desktop
  ปุ่ม "สแกนแบบ Full" จะเปิดโปรแกรมใหม่ และหน้าต่างของ Windows จะถามก่อนอ่านอะไร คุณเริ่มแทนผู้เล่นด้วย flag ไม่ได้
  การสแกนแบบมาตรฐานจะบอกครั้งเดียวที่ด้านบนว่ามีกี่รายการที่ตอบได้เฉพาะการสแกนแบบ Full
- **แถวโฟลเดอร์ cache ของเซิร์ฟเวอร์บอกแค่ว่าเกมเคยเข้าเซิร์ฟเวอร์** ชื่อจะแสดงเป็น `%SERVER_IDENTITY%` เว้นแต่ผู้เล่นยินยอม
  ให้แสดงชื่อเซิร์ฟเวอร์ด้วย ชื่อเดียวกันในรายงานสองฉบับจากเครื่องเดียวกันคือเซิร์ฟเวอร์เดียวกัน แต่ยังไม่รู้ว่าเครื่องอื่นได้ชื่อเดียวกันหรือไม่
  จึงอย่าเอาไปเทียบกับโฟลเดอร์บนเครื่องของคุณ
- **การไม่มีไม่ได้บอกอะไร** ผู้เล่นที่ไม่เคยใช้ GTA V Enhanced ติดตั้งใหม่ หรือลบโฟลเดอร์ไปแล้ว จะไม่มีแถวนี้

สองเรื่องที่ต้องรู้เกี่ยวกับ rule ไฟล์ hosts:

- **ให้ดูที่ชนิดของ address** `loopback` หรือ `unspecified` ทำให้ชื่อนั้นไม่ไปไหน ซึ่งเป็นวิธีที่ blocklist ใช้บล็อกบริการ
  ส่วน `private` หรือ `public` ส่งชื่อนั้นไปเครื่องอื่น โหมด SS แสดงแค่ชนิด เพราะ address เองอาจเป็นเซิร์ฟเวอร์ของผู้เล่น
  ถ้าต้องการรู้ให้ถามผู้เล่นเอง
- **อ่านการตั้งค่า ไม่ได้อ่าน traffic** โปรแกรมนี้ไม่อ่านว่าเครื่องเคยเชื่อมต่อไปที่ไหน ทั้ง DNS cache การเชื่อมต่อที่เปิดอยู่
  และ log ใด ๆ ของมัน ([ADR 0054](adr/0054-network-settings-not-network-traffic.md)) proxy กับ rule ของ Windows Firewall
  สำหรับ FiveM ก็ถูกอ่านด้วย แต่ไม่มี rule อ่านมัน เพราะโปรแกรม FiveM ที่ได้รับอนุญาตและการตั้ง proxy เป็นเรื่องปกติของเครื่องทั่วไป
  โหมด SS แสดงแค่จำนวน

rule posture ทั้งหมดบอกเรื่องของ **เครื่อง** ไม่ได้บอกเรื่องของคน ข้อความในตัว rule แต่ละตัวเขียนไว้เองว่า
ลำพังตัวมันไม่ใช่หลักฐานว่าโกง

ข้อความเต็มของ rule ทุกตัว รวมถึงว่าแต่ละตัวตรงกับอะไรบ้าง อยู่ใน[คู่มืออ้างอิง rule](rules-reference.th.md)

## 7. สิ่งที่โหมด SS ไม่แสดง และเพราะอะไร

โปรแกรมอ่านมากกว่าที่ rule ถาม มันอ่านสิ่งที่ Windows บันทึกไว้เกี่ยวกับโปรแกรมที่เคยรัน (Prefetch, BAM,
Program Compatibility Assistant) และรายชื่อโปรแกรมที่กำลังรัน **วันนี้ยังไม่มี rule
ไหนอ่านสิ่งเหล่านี้** (rule เดียวที่ว่าด้วย Prefetch ถามแค่ว่าไฟล์ถูกตั้งเป็นอ่านอย่างเดียวหรือไม่ ไม่ได้ถามว่าไฟล์บันทึกอะไร) มันจึงเป็น *สิ่งที่เห็นแต่ไม่ตรง rule ใดเลย*:

- **โหมดตรวจเครื่องตัวเอง** แสดงเป็นรายการให้ผู้เล่นดู
- **โหมด SS** แสดงแค่จำนวน ยกเว้นบน timeline

ตั้งใจให้เป็นแบบนี้ หน้ายินยอมสัญญาว่าจะแสดงสิ่งที่ตรง rule และ timeline ที่ระบุไว้ รายชื่อทุกโปรแกรมที่คนหนึ่งเคยรันจะบอกแอดมินว่า
เครื่องนั้นมีอะไรอีกบ้าง การซ่อนชื่อผู้ใช้ใน path ไม่ได้ทำให้เรื่องนี้เปลี่ยน
[ADR 0034](adr/0034-prefetch-bam-and-pca-carry-no-identity.md) อธิบายว่าทำไมไม่มี rule สำหรับสิ่งเหล่านี้: บันทึกพวกนี้
ระบุโปรแกรมได้แค่ด้วยชื่อไฟล์หรือ path เปลี่ยนชื่อไฟล์ก็หลบ rule แบบนั้นได้ และมันแยกโปรแกรมที่ถูกต้องซึ่งชื่อซ้ำกันไม่ออก

**timeline** (ADR 0051) เป็นข้อยกเว้นเดียว และหน้ายินยอมระบุชื่อโปรแกรมไว้ทีละตัว: สำหรับโปรแกรมที่ชื่อ
`FiveM.exe`, `GTA5.exe`, `GTA5_Enhanced.exe`, `PlayGTAV.exe` หรือ `FiveM_b<ตัวเลข>_GTAProcess.exe` โหมด SS
แสดงเวลาที่ Windows บันทึกไว้พร้อมชื่อ มันไม่ใช่แถวและไม่ใช่หลักฐาน Windows เก็บไว้แค่ชื่อ เวลาในนั้นจึงบอกว่า
โปรแกรม **ที่ชื่อนั้น** รันตอนนั้น ไม่ได้บอกว่าเกมรัน และการไม่มีเวลาก็ไม่ได้บอกว่าไม่เคยเล่นเกม timeline ยังแสดง
เวลาของโฟลเดอร์ log, crash และ cache ของ FiveM ช่วงที่ event log แต่ละตัวและ change journal ครอบคลุม และแหล่งไหน
อ่านไม่ได้ อ่านเวลาได้เฉพาะภายในช่วงที่แหล่งของมันครอบคลุม และอย่าอ่านช่องว่างระหว่างสองเวลาว่ามีคนลบอะไรไป

โหมดตรวจเครื่องตัวเองเป็นมุมมองของผู้เล่น ความยินยอมของผู้เล่นครอบคลุมโหมด SS การขอดูโหมดตรวจเครื่องตัวเอง
คือการขอสิ่งที่ผู้เล่นไม่ได้ยินยอมไว้

## 8. ร่องรอยของโปรแกรมนี้เอง

โปรแกรมกำลังรันอยู่ตอนสแกน จึงเห็นตัวเองด้วย ส่วน **ร่องรอยของโปรแกรมนี้เอง (แยกออกแล้ว)** ขึ้นในทั้งสองโหมด
และแสดงสิ่งที่มันเห็นของตัวเอง ส่วนนี้ไม่ใช่หลักฐานเกี่ยวกับเครื่อง

## 9. เก็บผลไว้

- **รุ่นที่มีหน้าต่างไม่มีปุ่ม export หรือบันทึก** ในรุ่น 0.3.0
- **CLI** เขียนมุมมองโหมด SS ออกเป็น JSON ได้ โดยซ่อนข้อมูลแบบเดียวกับบนจอ:

  ```powershell
  .\aeterna-rongroi-cli-0.3.0-windows-x64.exe scan --mode ss --json > report.json
  ```

  คำถามขอความยินยอมยังขึ้นบนจอ ผู้เล่นตอบบนจอได้ และไฟล์มีแค่ JSON ให้รันจาก PowerShell ที่เปิดด้วยสิทธิ์ผู้ดูแลระบบ
  (ข้อ 3) ไม่ใช่ใช้ `--elevate`

  **ถ้าใช้รุ่น 0.2.0** คำถามขอความยินยอมออกไปทางเดียวกับ JSON ถ้าใช้ `>` ผู้เล่นจะมองไม่เห็นคำถาม โปรแกรมจะรอคำตอบ
  โดยไม่มีอะไรขึ้นบนจอ และคำถามจะไปอยู่บรรทัดแรกของไฟล์ กับรุ่น 0.2.0 ให้รันสแกนโหมด SS ตามข้อ 4 แบบไม่มี `--json`
  ก่อน ผู้เล่นจะได้ตอบบนจอ ถ้าผู้เล่นยินยอม ค่อยรันคำสั่งข้างบนโดยเติม `--yes` นี่คือการสแกนรอบที่สอง
  รายชื่อโปรแกรมที่กำลังรันจึงอาจต่างจากบนจอเล็กน้อย
- ไฟล์ที่ผู้เล่นส่งให้แอดมินเป็นความรับผิดชอบของเซิร์ฟเวอร์ รวมถึงว่าจะเก็บไว้นานแค่ไหน ([PRIVACY.md](../PRIVACY.md))

## 10. สิ่งที่ห้ามสรุป

| รายงานแสดง | ไม่ได้แปลว่า |
|---|---|
| มีแถว `เจอ` | ผู้เล่นโกง |
| ไม่มีแถว `เจอ` เลย | เครื่องสะอาด |
| `ยังไม่ได้วัด` | ผู้เล่นซ่อนอะไรอยู่ |
| บรรทัดขอบเขตเรื่องสิทธิ์ผู้ดูแลระบบ | ผู้เล่นปฏิเสธอะไร |
| rule ล้าง log ขึ้นทั้งสองแถว | ล้างสองครั้งแยกกัน |
| log ถูกล้างจำนวนมาก | การล้างที่ร้ายแรงกว่า |
| แถว posture | อะไรเกี่ยวกับตัวคน |
| `Windows เริ่มทำงาน` หลายวันก่อนการสแกน | ผู้เล่นเลี่ยงการ restart หรือซ่อนอะไรอยู่ |
| `Windows เริ่มทำงาน` ไม่กี่นาทีก่อนการสแกน | ผู้เล่น restart เพื่อซ่อนอะไร |

ใช้รายงานเป็นหลักฐานชิ้นหนึ่งให้คนตัดสิน ประกอบกับสิ่งอื่นที่เซิร์ฟเวอร์รู้

## 11. สิ่งที่รายงานพิสูจน์เกี่ยวกับตัวเองไม่ได้

ข้อ 10 พูดถึงสิ่งที่แต่ละแถวบอก ข้อนี้พูดถึงตัวรายงาน

- **รายงานไม่ได้ถูกเซ็น** ไฟล์ที่มีคนส่งให้หลังจบการตรวจเป็นแค่ข้อความ ใครก็ตามที่เคยถือไฟล์นั้นแก้มันได้
  และในไฟล์ไม่มีอะไรบอกได้ว่าไม่มีใครแก้
- **`build ทางการ` กับ `exe sha256` คือสิ่งที่โปรแกรมที่กำลังรันบอกเกี่ยวกับตัวเอง** มีไว้ช่วยให้สังเกต build
  ที่ไม่เป็นทางการได้ง่าย โปรแกรมที่ถูกแก้ก็พิมพ์บรรทัดเดียวกันออกมาได้ (ข้อ 2)
- **โปรแกรมตัวจริงที่ไม่ถูกแก้ ก็ยังรายงานตามที่ Windows บอกมัน** ถ้า Windows บนเครื่องนั้นถูกแก้ให้หลอกโปรแกรมที่รันอยู่บนมัน
  โปรแกรมตัวจริงก็จะแสดงและเขียนตามที่ถูกบอก (ข้อ 1)
- **สิ่งที่เชื่อได้คือสิ่งที่เห็นกับตา:** การโหลดจากหน้า Releases, hash, ส่วนหัว, ผู้เล่นตอบคำถามขอความยินยอม,
  แถวที่ขึ้นมาบนจอ ไฟล์ที่ส่งมาทีหลังมีค่าเท่ากับการตรวจรอบนั้นเท่านั้น
- **ถ้ามีเครื่องมือไหนเสนอรายงานที่ "เซ็นแล้ว" หรือ "ปลอมไม่ได้" ให้ถามว่า key อยู่ที่ไหน และใครเป็นคนตรวจลายเซ็น**
  key ที่อยู่ในโปรแกรมที่ผู้เล่นเปิดเอง ก็อยู่บนเครื่องของผู้เล่น
