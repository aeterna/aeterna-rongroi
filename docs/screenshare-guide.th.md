# คู่มือตรวจเครื่องระหว่างแชร์หน้าจอ

สำหรับแอดมินเซิร์ฟเวอร์ที่ตรวจเครื่องผู้เล่นผ่านการแชร์หน้าจอ และสำหรับผู้เล่นที่ถูกตรวจ ใช้กับ aeterna-rongroi
**0.2.0** · Read in English: [screenshare-guide.md](screenshare-guide.md)

> ⚠️ **ยังเป็นรุ่นทดลอง (pre-alpha)** ตอนนี้มี rule 6 ตัว และ 5 ตัวยังเป็น `experimental` อย่าแบนใครเพราะสิ่งที่
> โปรแกรมนี้แสดง และอย่าใช้มันยืนยันว่าใครไม่ผิด

## 1. แสดงอะไรได้ และแสดงอะไรไม่ได้

| แสดงได้ | แสดงไม่ได้ |
|---|---|
| การตั้งค่าเครื่องที่ทำให้โปรระดับ kernel โหลดได้ง่ายขึ้น ได้แก่ Secure Boot, test signing, memory integrity (HVCI), TPM | โปรที่รันบน **เครื่องที่สอง** (DMA) ซึ่งไม่ทิ้งอะไรไว้บนเครื่องที่ถูกตรวจ |
| ว่า Security log หรือ event log ไฟล์หนึ่งมีบันทึกว่าตัวเองถูกล้าง | overlay ที่ซ่อนตัวจากการจับภาพหน้าจอ |
| ว่าการตรวจแต่ละข้อได้คำตอบไหม ถ้าไม่ได้ ติดอะไร | อะไรเลย ถ้า Windows บนเครื่องนั้นถูกแก้ให้หลอกโปรแกรมที่รันอยู่บนมัน |
| | ว่าเครื่องสะอาด **ไม่มีผลลัพธ์ข้อไหนแปลว่าอย่างนั้น** |

ทุกแถวเป็นหนึ่งในสามสถานะ **เจอ** แสดงหลักฐาน **ไม่เจอ** บอกว่าแหล่งนั้นย้อนดูได้ไกลแค่ไหน **ยังไม่ได้วัด** บอกเหตุผล
คนเป็นผู้ตัดสินว่าแต่ละแถวหมายถึงอะไร โปรแกรมไม่ตัดสินเอง

## 2. โหลดไฟล์ตัวจริง

1. ให้ผู้เล่นโหลดเองจากหน้า **Releases** ของโปรเจกต์บน GitHub ส่งลิงก์หน้านั้นให้ผู้เล่น อย่าส่งไฟล์ให้เอง
   - `aeterna-rongroi-cli-0.2.0-windows-x64.exe` คือรุ่นบรรทัดคำสั่ง ไม่ใช้ WebView2
   - `aeterna-rongroi-0.2.0-windows-x64.exe` คือรุ่นที่มีหน้าต่าง
2. อย่าเปิดไฟล์จากเบราว์เซอร์ Windows SmartScreen จะขึ้นเตือน เพราะ release ยังไม่ได้เซ็นโค้ด และต้องเช็ค hash ก่อน
3. ก่อนเปิดโปรแกรม ให้ผู้เล่นเปิด PowerShell ในโฟลเดอร์ที่โหลดไฟล์มา แล้วรัน:

   ```powershell
   Get-FileHash .\aeterna-rongroi-*-windows-x64.exe
   ```

   เทียบ hash กับบรรทัดของไฟล์ชื่อเดียวกันใน `SHA256SUMS` บนหน้า release ตัวพิมพ์เล็กหรือใหญ่ไม่มีผล
4. เมื่อ hash ตรงแล้วเท่านั้น: `Unblock-File .\<ชื่อไฟล์>` จะเอาเครื่องหมาย "โหลดมาจากอินเทอร์เน็ต" ออกจากไฟล์นั้นไฟล์เดียว
   ถ้า SmartScreen ยังขึ้น **Windows protected your PC** ให้กด **More info** ดูชื่อแอป แล้วกด **Run anyway**
   ช่อง publisher จะขึ้นว่าไม่รู้จักจนกว่า release จะเซ็นโค้ด อย่าปิด SmartScreen ทั้งเครื่อง
5. ตอนรัน ส่วนหัวต้องขึ้นว่า **build ทางการ** ถ้าขึ้น **UNOFFICIAL BUILD** หรือ hash ไม่ตรง **ให้หยุด** ผลตรวจใช้ไม่ได้

ส่วนหัวของรายงานพิมพ์ `exe sha256` ของตัวโปรแกรมเองด้วย ค่านี้ควรตรงกับ `SHA256SUMS` ถ้าตรง แปลว่าไฟล์ที่รันอยู่
สอดคล้องกับ release แต่พิสูจน์ไม่ได้ เพราะโปรแกรมที่ถูกแก้จะพิมพ์ค่าอะไรออกมาก็ได้

## 3. สิทธิ์ผู้ดูแลระบบ

การตรวจบางข้อต้องใช้สิทธิ์ผู้ดูแลระบบ รายงานจะบอกจำนวนไว้บรรทัดเดียวเหนือหลักฐาน:

> ขอบเขตการตรวจ: มี N รายการที่ตอบไม่ได้เพราะการสแกนครั้งนี้ไม่มีสิทธิ์ผู้ดูแลระบบ
> เปิดใหม่ด้วยสิทธิ์ผู้ดูแลระบบแล้วจะตอบได้

บรรทัดนี้ไม่ใช่สิ่งที่ตรวจเจอ มันบอกว่าการสแกนรอบนี้ตอบรายการเหล่านั้นไม่ได้ ผลที่วัดบนเครื่อง Windows 11
หนึ่งเครื่องตอนไม่มีสิทธิ์ผู้ดูแลระบบ: Prefetch กับ BAM แทบไม่ได้อะไร rule ล้าง log ทั้งสองตัวออกมาเป็น *ยังไม่ได้วัด*
ส่วน rule posture ทั้งสี่ตัวกับ PCA ทำงานปกติ

- **รุ่นที่มีหน้าต่าง:** ที่หน้าแรก กด **ตรวจด้วยสิทธิ์ผู้ดูแลระบบ** แล้วกดยอมรับในหน้าต่างที่ Windows ถาม โปรแกรมจะปิด
  แล้วเปิดใหม่ด้วยสิทธิ์นั้น และเริ่มสแกนใหม่ทั้งหมด ปุ่มนี้ขึ้นเฉพาะตอนที่การสแกนรอบนั้นไม่มีสิทธิ์ผู้ดูแลระบบ
- **CLI:** เปิด **PowerShell แบบ Run as administrator** แล้วสแกนในหน้าต่างนั้น (ข้อ 4)
  ถ้าใช้รุ่น 0.2.0 อย่าใช้ `--elevate` เพราะมันจะสแกนใน **หน้าต่าง console ใหม่** และ Windows ปิดหน้าต่างนั้นทันทีที่
  สแกนเสร็จ รายงานหายไปพร้อมหน้าต่าง (วัดบนเครื่อง Windows 11 จริง [ADR 0012](adr/0012-elevation-relaunch.md))
  รุ่นหลัง 0.2.0 จะเปิดหน้าต่างค้างไว้จนกว่าจะกด Enter แต่ไม่ว่ารุ่นไหน รายงานจาก `--elevate` จะอยู่ในหน้าต่างนั้น
  และไม่เข้าไฟล์ที่ redirect ด้วย `>`

ผู้เล่นปฏิเสธสิทธิ์ผู้ดูแลระบบได้ การสแกนยังรันได้ แค่มีรายการในบรรทัดขอบเขตมากขึ้น

## 4. สแกนแบบโหมด SS

โหมด SS คือมุมมองสำหรับแชร์หน้าจอ ขอความยินยอมจากผู้เล่นก่อน แสดงเฉพาะสิ่งที่ตรง rule และเปลี่ยนโฟลเดอร์ผู้ใช้
ใน path เป็น `%USERPROFILE%`

**รุ่นที่มีหน้าต่าง:** **ตรวจระหว่างแชร์หน้าจอ (โหมด SS)** → อ่านหน้ายินยอม → **ยินยอม — แสดงผลโหมด SS**
รุ่นนี้สแกนตอนเปิดโปรแกรม **ก่อน** หน้าต่างจะขึ้น หน้าต่างจึงเปลี่ยนผลไม่ได้ หน้ายินยอมมีผลแค่ว่าจะแสดงอะไร

**CLI:**

```powershell
.\aeterna-rongroi-cli-0.2.0-windows-x64.exe scan --mode ss --lang th
```

โปรแกรมจะถาม `ดำเนินการต่อ? [y/N]` และ **ผู้เล่น** เป็นคนตอบ

- **อย่าใช้ `--yes` ข้ามคำถามที่ผู้เล่นยังไม่ได้ตอบ** flag นี้มีไว้สำหรับผู้เล่นที่ยินยอมไปแล้ว (ข้อ 9)
- ถ้าผู้เล่นปฏิเสธ โปรแกรมจะพิมพ์ `ยกเลิกการสแกนแล้ว ไม่ได้อ่านอะไรเลย` และไม่อ่านอะไร ส่วนเซิร์ฟเวอร์จะทำอะไร
  หลังผู้เล่นปฏิเสธ เป็นกติกาของเซิร์ฟเวอร์ ไม่ใช่สิ่งที่โปรแกรมนี้วัด

## 5. อ่านรายงาน

### ส่วนหัว

```
aeterna-rongroi 0.2.0
build ทางการ
mode: ss · windows <build> · สิทธิ์ผู้ดูแลระบบ · rules: 6 (<bundle hash>)
exe sha256: <hash>
```

ดูสี่อย่าง: `build ทางการ`, `mode: ss`, ขึ้นว่า `สิทธิ์ผู้ดูแลระบบ` หรือ `ผู้ใช้ทั่วไป`, และจำนวน rule

### แต่ละแถว

```
[เจอ] ตรวจ: <ชื่อ rule>  (<strength>, <collector>)
    <หลักฐาน>
    เกี่ยวกับการตรวจนี้: <การตรวจนี้หมายถึงอะไร และพิสูจน์อะไรไม่ได้>
    เรื่องปกติที่ทำให้เกิดผลแบบนี้ได้เหมือนกัน:
      - …
```

- **`ตรวจ:`** อยู่หน้าชื่อ เพราะชื่อ rule บอกว่า rule มองหาอะไร ไม่ได้บอกว่าเห็นอะไร
- **strength** บอกว่า rule ให้หลักฐานแบบไหน `tamper`: ร่องรอยถูกลบหรือถูกแก้ `posture`: การตั้งค่าเครื่องที่ทำให้โกงง่ายขึ้น
  `context`: ข้อมูลพื้นหลังให้คนตรวจ (มี `execution` กับ `presence` ด้วย แต่ยังไม่มี rule ไหนใช้)
- **เรื่องปกติที่ทำให้เกิดผลแบบนี้ได้เหมือนกัน** ขึ้นข้างทุกแถวที่ `เจอ` **ให้อ่านออกเสียง** ทุก rule ต้องมีส่วนนี้
  และเป็นส่วนที่คนมักข้ามมากที่สุด
- **`ยังไม่ได้วัด (เป็นเรื่องปกติของเครื่องนี้)`** แปลว่าคนเขียน rule ระบุไว้ว่าสภาพเครื่องแบบนี้เป็นเรื่องปกติ
  **`ยังไม่ได้วัด (ไม่ได้คาดไว้)`** แปลว่าไม่ได้คาดไว้ ทั้งสองแบบไม่ใช่สิ่งที่ตรวจเจอ

### บรรทัดท้าย

```
ซ่อนในโหมด SS: ไม่เจอ <n> · ยังไม่ได้วัด (เป็นเรื่องปกติของเครื่องนี้) <n> · ยังไม่ได้วัด (ไม่ได้คาดไว้) <n> · สิ่งที่เห็นแต่ไม่ตรง rule ใดเลย <n>
```

เป็นจำนวนของสิ่งที่โหมด SS ไม่ได้แสดงเป็นรายการ เหตุผลอยู่ในข้อ 7

## 6. rule ทั้ง 6 ตัว และเรื่องปกติที่ทำให้เกิดผลแบบเดียวกัน

| rule | strength | status | เรื่องปกติที่ทำให้เกิด (สรุปจากตัว rule เอง) |
|---|---|---|---|
| Secure Boot ถูกปิดอยู่ | posture | `test` | บูตแบบ legacy BIOS/CSM, ลงสองระบบ, ปิดเพื่อใช้เครื่องมือฮาร์ดแวร์หรือโอเวอร์คล็อก |
| เปิดโหมด test signing ของ Windows อยู่ | posture | `experimental` | คนเขียนหรือทดสอบ driver, วิศวกรฮาร์ดแวร์, ซอฟต์แวร์ที่คู่มือติดตั้งสั่งให้เปิด |
| ตั้งค่า Memory integrity (HVCI) ไว้เป็นปิด | posture | `experimental` | ฮาร์ดแวร์ไม่รองรับ, ปิดเพื่อแก้ driver ชนกัน, เครื่องจำนวนมากปิดมาตั้งแต่แรก |
| เครื่องนี้ไม่มี TPM | context | `experimental` | เครื่องเก่าหรือประกอบเอง, ปิด TPM ไว้ใน firmware, virtual machine |
| Security log มีบันทึกว่าตัวเองถูกล้าง | tamper | `experimental` | สคริปต์ "optimiser" หรือ "debloat", เครื่องประกอบสำเร็จหรือเพิ่งซ่อม, ล้าง log ใน Event Viewer ตอนแก้ปัญหา, อัปเดต Windows |
| มี event log ไฟล์หนึ่งถูกล้าง | tamper | `experimental` | เหมือนข้างบน และซอฟต์แวร์ที่รีเซ็ต log ตอนติดตั้ง |

สามเรื่องที่ต้องรู้เกี่ยวกับ rule ล้าง log สองตัวนี้:

- **สองแถวอาจเป็นการกระทำเดียวกัน** การล้าง Security log ถูกบันทึกได้ในทั้งสอง log
- **จำนวนมากชี้ไปทาง optimiser ไม่ได้ชี้ว่าร้ายแรงกว่า** สคริปต์พวกนั้นล้างทุก log พร้อมกันในคลิกเดียว
- **ทั้งสองตัวขึ้นบนเครื่อง Windows ของ GitHub Actions** ซึ่งเป็นเครื่องที่สร้างจาก image และไม่มีใครกล่าวหาอะไร
  ขั้นตอนเตรียม image ของ Windows ลบ event log ทิ้ง rule ทำงานตามที่เขียนไว้ และนี่คือหน้าตาของแถว `tamper`
  บนเครื่องธรรมดา

rule posture ทั้งสี่ตัวบอกเรื่องของ **เครื่อง** ไม่ได้บอกเรื่องของคน ข้อความในตัว rule แต่ละตัวเขียนไว้เองว่า
ลำพังตัวมันไม่ใช่หลักฐานว่าโกง

ข้อความเต็มของ rule ทุกตัว รวมถึงว่าแต่ละตัวตรงกับอะไรบ้าง อยู่ใน[คู่มืออ้างอิง rule](rules-reference.th.md)

## 7. สิ่งที่โหมด SS ไม่แสดง และเพราะอะไร

โปรแกรมอ่านมากกว่าที่ rule ทั้ง 6 ตัวถาม มันอ่านสิ่งที่ Windows บันทึกไว้เกี่ยวกับโปรแกรมที่เคยรัน (Prefetch, BAM,
Program Compatibility Assistant) รายชื่อโปรแกรมที่กำลังรัน และไฟล์ในโฟลเดอร์ plugin ของ FiveM ทั้ง GTA V Legacy และ Enhanced พร้อมลายเซ็น **วันนี้ยังไม่มี rule
ไหนอ่านสิ่งเหล่านี้** มันจึงเป็น *สิ่งที่เห็นแต่ไม่ตรง rule ใดเลย*:

- **โหมดตรวจเครื่องตัวเอง** แสดงเป็นรายการให้ผู้เล่นดู
- **โหมด SS** แสดงแค่จำนวน

ตั้งใจให้เป็นแบบนี้ หน้ายินยอมสัญญาว่าจะแสดง "เฉพาะสิ่งที่ตรง rule" รายชื่อทุกโปรแกรมที่คนหนึ่งเคยรันจะบอกแอดมินว่า
เครื่องนั้นมีอะไรอีกบ้าง การซ่อนชื่อผู้ใช้ใน path ไม่ได้ทำให้เรื่องนี้เปลี่ยน
[ADR 0034](adr/0034-prefetch-bam-and-pca-carry-no-identity.md) อธิบายว่าทำไมไม่มี rule สำหรับสิ่งเหล่านี้: บันทึกพวกนี้
ระบุโปรแกรมได้แค่ด้วยชื่อไฟล์หรือ path เปลี่ยนชื่อไฟล์ก็หลบ rule แบบนั้นได้ และมันแยกโปรแกรมที่ถูกต้องซึ่งชื่อซ้ำกันไม่ออก

โหมดตรวจเครื่องตัวเองเป็นมุมมองของผู้เล่น ความยินยอมของผู้เล่นครอบคลุมโหมด SS การขอดูโหมดตรวจเครื่องตัวเอง
คือการขอสิ่งที่ผู้เล่นไม่ได้ยินยอมไว้

## 8. ร่องรอยของโปรแกรมนี้เอง

โปรแกรมกำลังรันอยู่ตอนสแกน จึงเห็นตัวเองด้วย ส่วน **ร่องรอยของโปรแกรมนี้เอง (แยกออกแล้ว)** ขึ้นในทั้งสองโหมด
และแสดงสิ่งที่มันเห็นของตัวเอง ส่วนนี้ไม่ใช่หลักฐานเกี่ยวกับเครื่อง

## 9. เก็บผลไว้

- **รุ่นที่มีหน้าต่างไม่มีปุ่ม export หรือบันทึก** ในรุ่น 0.2.0
- **CLI** เขียนมุมมองโหมด SS ออกเป็น JSON ได้ โดยซ่อนข้อมูลแบบเดียวกับบนจอ:

  ```powershell
  .\aeterna-rongroi-cli-0.2.0-windows-x64.exe scan --mode ss --json > report.json
  ```

  **รุ่นหลัง 0.2.0:** คำถามขอความยินยอมยังขึ้นบนจอ ผู้เล่นตอบบนจอได้ และไฟล์มีแค่ JSON

  **รุ่น 0.2.0:** คำถามขอความยินยอมออกไปทางเดียวกับ JSON ถ้าใช้ `>` ผู้เล่นจะมองไม่เห็นคำถาม โปรแกรมจะรอคำตอบ
  โดยไม่มีอะไรขึ้นบนจอ และคำถามจะไปอยู่บรรทัดแรกของไฟล์ ถ้าใช้ 0.2.0 ให้รันสแกนโหมด SS ตามข้อ 4 แบบไม่มี `--json`
  ก่อน ผู้เล่นจะได้อ่านคำถามและตอบบนจอ ถ้าผู้เล่นยินยอม ค่อยรันคำสั่งข้างบนโดยเติม `--yes` ซึ่งเป็นสิ่งที่ `--yes`
  มีไว้ทำ นี่คือการสแกนรอบที่สอง รายชื่อโปรแกรมที่กำลังรันจึงอาจต่างจากบนจอเล็กน้อย

  ไม่ว่ารุ่นไหน ให้รันจาก PowerShell ที่เปิดด้วยสิทธิ์ผู้ดูแลระบบ (ข้อ 3) ไม่ใช่ใช้ `--elevate`
- ไฟล์ที่ผู้เล่นส่งให้แอดมินเป็นความรับผิดชอบของเซิร์ฟเวอร์ รวมถึงว่าจะเก็บไว้นานแค่ไหน ([PRIVACY.md](../PRIVACY.md))

## 10. สิ่งที่ห้ามสรุป

| รายงานแสดง | ไม่ได้แปลว่า |
|---|---|
| มีแถว `เจอ` | ผู้เล่นโกง |
| ไม่มีแถว `เจอ` เลย | เครื่องสะอาด |
| `ยังไม่ได้วัด` | ผู้เล่นซ่อนอะไรอยู่ |
| บรรทัดขอบเขตเรื่องสิทธิ์ผู้ดูแลระบบ | ผู้เล่นปฏิเสธอะไร |
| rule ล้าง log ขึ้นทั้งสองแถว | ล้างสองครั้งแยกกัน |
| log ถูกล้างจำนวนมาก | การล้างที่ร้ายแรงกว่า |
| แถว posture | อะไรเกี่ยวกับตัวคน |

ใช้รายงานเป็นหลักฐานชิ้นหนึ่งให้คนตัดสิน ประกอบกับสิ่งอื่นที่เซิร์ฟเวอร์รู้

## 11. สิ่งที่รายงานพิสูจน์เกี่ยวกับตัวเองไม่ได้

ข้อ 10 พูดถึงสิ่งที่แต่ละแถวบอก ข้อนี้พูดถึงตัวรายงาน

- **รายงานไม่ได้ถูกเซ็น** ไฟล์ที่มีคนส่งให้หลังจบการตรวจเป็นแค่ข้อความ ใครก็ตามที่เคยถือไฟล์นั้นแก้มันได้
  และในไฟล์ไม่มีอะไรบอกได้ว่าไม่มีใครแก้
- **`build ทางการ` กับ `exe sha256` คือสิ่งที่โปรแกรมที่กำลังรันบอกเกี่ยวกับตัวเอง** มีไว้ช่วยให้สังเกต build
  ที่ไม่เป็นทางการได้ง่าย โปรแกรมที่ถูกแก้ก็พิมพ์บรรทัดเดียวกันออกมาได้ (ข้อ 2)
- **โปรแกรมตัวจริงที่ไม่ถูกแก้ ก็ยังรายงานตามที่ Windows บอกมัน** ถ้า Windows บนเครื่องนั้นถูกแก้ให้หลอกโปรแกรมที่รันอยู่บนมัน
  โปรแกรมตัวจริงก็จะแสดงและเขียนตามที่ถูกบอก (ข้อ 1)
- **สิ่งที่เชื่อได้คือสิ่งที่เห็นกับตา:** การโหลดจากหน้า Releases, hash, ส่วนหัว, ผู้เล่นตอบคำถามขอความยินยอม,
  แถวที่ขึ้นมาบนจอ ไฟล์ที่ส่งมาทีหลังมีค่าเท่ากับการตรวจรอบนั้นเท่านั้น
- **ถ้ามีเครื่องมือไหนเสนอรายงานที่ "เซ็นแล้ว" หรือ "ปลอมไม่ได้" ให้ถามว่า key อยู่ที่ไหน และใครเป็นคนตรวจลายเซ็น**
  key ที่อยู่ในโปรแกรมที่ผู้เล่นเปิดเอง ก็อยู่บนเครื่องของผู้เล่น
  [ADR 0040](adr/0040-reports-are-not-signed.md) (ภาษาอังกฤษ) อธิบายว่าทำไมโปรเจกต์นี้ไม่เซ็นรายงาน
